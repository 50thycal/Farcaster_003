# PR-002.5 — Exact User Lookup (Free-Plan Path) + Users UI Auto-Route

Adds exact user lookup functionality that works on Neynar's free/Beginner plan, with intelligent query routing.

## Changes

**app/api/users/get/route.ts** (new)
- Exact user lookup by `@username` or `fid`
- Two endpoints in one: `?username=handle` or `?fid=123`
- Works on Neynar free plan (no search tier required)
- Returns normalized user object matching app schema

**app/users/page.tsx**
- Intelligent query routing based on input type
- Detects FID (numeric) → exact lookup via `/api/users/get?fid=`
- Detects handle (@username or alphanumeric) → exact lookup via `/api/users/get?username=`
- Falls back to full-text search for other queries
- Friendly 402 error messaging explaining plan limitations
- Updated placeholder: `"@v  or  2  or  'varun'"`
- Help text explaining free vs paid features

## Problem Solved

Neynar's full-text search endpoint (`/user/search`) requires a paid plan tier. Free/Beginner plan users get 402 errors when trying to search.

However, exact lookups by username or FID are available on the free plan via:
- `/user-by-username?username=`
- `/user?fid=`

This PR enables free-plan users to:
- Look up exact users by `@handle` or FID
- Get clear messaging when full-text search requires upgrade
- Still have fallback to search for partial matches (with helpful 402 message)

## User Experience

**Example queries:**
- `@v` or `v` → Exact lookup for user "v" (works on free plan) ✅
- `2` → Exact lookup for FID 2 (works on free plan) ✅
- `varun` → Falls back to search, may 402 with friendly message ⚠️

**Error messaging:**
- 402 errors show yellow banner: _"Full-text search is gated on the current Neynar plan. Exact lookups by @handle or FID still work."_
- Other errors show original error message

## Acceptance Criteria

✓ `GET /api/users/get?username=v` returns user object (HTTP 200)
