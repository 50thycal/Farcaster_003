# PR-002.1 — Fix Neynar Header + Surface API Errors

Critical fix for Neynar API authentication and improved error visibility in UI.

## Changes

**lib/neynar.ts**
- Fixed authentication header from `api_key` to `x-api-key`
- This resolves the 402 Payment Required errors

**app/users/page.tsx**
- Added error state display with red text
- Added `normalizeQ()` to strip `@` prefix from queries
- Clear error/data on new search
- Show detailed error messages (status + message)

**app/graph/page.tsx**
- Added error state display with red text
- Clear error/data on new load
- Show detailed error messages (status + message)
- Errors now visible instead of silent failures

## Problem Solved

The Neynar API requires the `x-api-key` header, not `api_key`. This was causing all requests to fail with 402 errors even with valid API keys.

Additionally, errors were silently failing in the UI with no user feedback.

## Acceptance Criteria

✓ Neynar API calls succeed with valid API key
✓ User search returns real results
✓ Graph endpoints (followers/following) return real data
✓ Error messages display in red when API calls fail
✓ Users see clear feedback for 402, 404, 500, etc. errors
✓ Build succeeds without errors
